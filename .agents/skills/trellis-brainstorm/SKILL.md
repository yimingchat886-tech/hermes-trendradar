# Brainstorm

Use this only when product behavior, architecture, public API, dependency,
migration, irreversible effect, or multiple reasonable choices remain open.

1. Inspect repository facts before asking.
2. Ask one material question at a time, with a recommendation and trade-off.
3. Keep one PRD with goal, scope, out-of-scope, owned REQ IDs, acceptance,
   logical checks, and risks.
4. “采纳”, “记录”, and “确认方向” update Draft only.
5. “确认方案并开始执行” accepts the shown revision, authorizes one scoped PRD
   commit, appends its immutable binding generation, and starts the same
   default Loop.
6. Material later revisions append generations to the same run. Never create a
   successor or child Task.

A clear small bug skips this skill and uses the minimal intent snapshot path.
